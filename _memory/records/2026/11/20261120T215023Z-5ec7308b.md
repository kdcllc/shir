Pitfall (g10-setlists): .docx export tests that inspect only word/document.xml passed while the rendered document was wrong.

What went wrong: three real layout defects survived green XML-level unit tests and were found only by evaluators rendering the file in LibreOffice: (1) docx 9.15.2 writes equal-split w:tblGrid columns when columnWidths is not set, so a chord split inside a word ("rock and r" | "oll") showed a ~2 cm gap and dense lines spread across the page; (2) after content-sizing the columns, w:bidiVisual tables were placed at the LEFT margin (needed table jc=right); (3) chord paragraphs marked w:bidi rendered "F#" as "#F" in RTL cells (trailing '#' is a neutral). A plan-level width estimate (one constant per character) also made bold chords wrap.

How detected: `soffice --headless --convert-to pdf out.docx` then `pdftotext -bbox-layout out.pdf out.html`, measuring word boxes (gap between cells, chord xMax vs syllable xMax, single baseline per cell, right-margin x).

How to avoid: make a LibreOffice render + bbox measurement an acceptance criterion for any docx layout change (fixtures: mixed_he_en at t2 for F#, dense_chords, chord_only_line); derive widths from real font hmtx data, never a guessed per-character constant; keep chord text out of bidi paragraphs.
