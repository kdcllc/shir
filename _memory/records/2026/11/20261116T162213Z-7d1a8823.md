Pitfall: prettier only reads .prettierignore from the directory it runs in. During G5 a worker ran `pnpm exec prettier --write src …` from inside apps/desktop. It rewrote the generated, root-ignored apps/desktop/src/bindings.ts (tabs became spaces, lines were wrapped). That broke the bindings drift test for a sibling task in the same checkout, and wrote outside the worker's fence.

How detected: the sibling's full cargo test failed only on bindings_are_current. The orchestrator's post-group fence check then mapped the path to no fence. `prettier --check` from the repo root passed, because there the file is ignored.

Avoid:
- Run write-mode formatters only from the repo root and only on explicit, fenced file paths. Never run them on a directory from inside a package.
- Put this rule in every worker package that touches TS/JSON.
- Restore generated files from git, never re-format them.
- After every parallel group, map `git status --porcelain --untracked-files=all` against each member's fence before evaluation.
