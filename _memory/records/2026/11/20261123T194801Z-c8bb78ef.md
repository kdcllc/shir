Pitfall (g12-follow-ups): a plain `cargo build` / `cargo test` of apps/desktop/src-tauri rebuilds `target/debug/shir` WITHOUT the embedded frontend (no custom-protocol / dist), overwriting the binary that `pnpm tauri build --debug --no-bundle` produced for the WebdriverIO e2e suite.

What went wrong: the real-app e2e specs passed in task 10's evaluation, then a later Rust test run silently replaced the debug binary. The QA evidence-collector's WDIO run failed every spec in its before-all hook with "the Shir window never rendered the song pane" (waitForShell timeout), with empty app logs, which looked like an app regression.

How it was detected: the orchestrator compared the binary's mtime (13:49) with the build the e2e evaluator had used (13:27) and saw no app source had changed since. Rebuilding with `pnpm tauri build --debug --no-bundle` made all five specs pass again (print 2, setlists 8, ai-import 2, editor 2, library 6).

How to avoid: always rebuild with `pnpm tauri build --debug --no-bundle` immediately before a WDIO run that follows any cargo test/build; consider a harness pre-check that the binary is newer than target/debug/build outputs, or that it embeds the frontend.
