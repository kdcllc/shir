Decision (g12-follow-ups): the Word-export IPC payload (`save_export_docx`, up to 20 MiB) is sent as a base64 `String` argument (`bytes_base64` / binding `bytesBase64: string`) instead of a JSON number array.

Alternatives considered: (1) a true raw IPC body via `tauri::ipc::Request` — rejected because the pinned tauri 2.12.5 + tauri-specta 2.0.0-rc.29 have no specta `TAURI_REQUEST` stand-in, so the command would have to leave the typed bindings and be registered through a separate generate_handler!, rewriting the g10 contract tests; (2) upgrading tauri/tauri-specta — widest blast radius.

Rationale: base64 costs about 1.33x the byte count versus about 3.5x for a JSON number array, keeps the command typed and in bindings.ts, and needs only the already-resolved `base64 = 0.23.1` crate. Consequences: Rust caps the encoded length before decoding (MAX_EXPORT_BASE64_LEN = ceil(20 MiB / 3) * 4 = 27,962,028) and still validates the decoded size; the TS wrapper keeps a Uint8Array signature and encodes in 0x8000-byte chunks (a single spread overflows the stack at ~5 MiB); the Playwright web stub decodes `bytesBase64` with a fallback to the old `bytes` field. Revisit if tauri-specta gains a typed raw-request argument.
