Pitfall: tool-chain facts that broke G4 plans before any code was written. Each was found only by running the real tool, not by reading docs.

- Crate peer ranges: STACK.md planned rusqlite 0.42.0, but rusqlite_migration 2.7.0 requires rusqlite ^0.41 and refinery 0.10.0 requires <=0.40; two libsqlite3-sys versions cannot link. Check `crates.io/api/v1/crates/<c>/<v>/dependencies` for every pairing before pinning.
- No stable specta 2.x exists (2.0.0-rc.28; tauri-specta rc.29 is the latest compatible); the repo's stack guard forbade pre-releases, so a named allowlist was needed. tauri-specta defaults to ErrorHandlingMode::Throw, which drops the error type from generated TS — set Result explicitly. Its JS output renders commands as `name: (args) => …` object fields, and types are split by serde phase (`Song_Serialize | Song_Deserialize`).
- `xvfb-run` merges the child's stderr into stdout (/usr/bin/xvfb-run:184): a criterion that greps the app's stderr file always sees nothing. Capture one combined log.
- A read-only XDG_DATA_HOME makes Tauri panic in setup (WebKit data dirs live there) before product code runs; to simulate an unopenable DB, put a directory at the shir.db path instead.
- Tauri keeps only the last `.setup(...)`: merge new startup work into the existing smoke closure.
- `tauri_build` with `AppManifest::commands` generates untracked `src-tauri/permissions/autogenerated/*.toml` on every build; git-ignore it like gen/schemas.
- On windows-latest, a cmd stub that `echo`es thousands of lines to a redirected file is slow and variable (8→21.7 s); write payloads in one `type`. PowerShell `ReadAllLines` opens with FileShare.Read (Get-Content used ReadWrite) — use File.Open(..., ReadWrite) + StreamReader so a lingering child holding the handle cannot fake a missing marker.

Avoid: during Phase 2/3, run each live or tool-dependent acceptance criterion once on the real binary/tool and record its output; treat "verified by reading" as unverified.
