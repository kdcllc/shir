Goal g7-visual-editor-delete — outcome: shipped (branch feat/g7-visual-editor-delete, base ccb91aa).

What it delivered: the desktop song editor gained a Visual tab (default) next to the Source tab. The Visual tab shows the song with the real chord renderer (`ChordLine` in editing mode): click a letter to add a chord, chord picker with key-aware suggestions, move chords left/right in visual order on Hebrew, English and mixed lines, type lyrics per row, section controls, a song-details form (title, artist, key, capo, tempo), undo/redo and permanent transpose. Songs can be deleted from a list row, from the open song and in bulk through select mode, always behind an in-app confirm dialog. No Rust, IPC or schema change: bulk delete is a loop over the existing `deleteSong`.

Key decisions: ChordPro text stays the single source of truth; every visual action is an `EditOp` applied by chord-core `applyEdits(song, ops)`, which serializes and reparses, and the result goes into one text history (`useHistory`). `VisualEditor` is controlled and keeps only UI state. Left/right in the UI is visual; indices in ops are logical grapheme indices (`visualOrder`/`visualStep` in apps/desktop/src/visualKeys.ts).

Shape of the work: 15 tasks — contract first; chord-core edit / chord-render editing / widgets in parallel; delete UI and VisualEditor in parallel; a corrective print-rule task 05a; the editor shell; a closing test task; then, after the PR draft, six parallel backlog-fix tasks 09a–09f at the user's request ("include as many as possible fixes with this pr"). Phase 3 needed 4 attempts; Phase 5 needed 3 audits (audit 3 after the backlog fixes); docs were aligned in two rounds. Mid-goal the Fable model's usage limit ran out; the user switched every subagent to its frontmatter pin (evaluator Opus, implementer/test-writer Sonnet, terminal Haiku).
