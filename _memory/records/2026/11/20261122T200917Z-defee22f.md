Pitfall: an E2E spec whose test song title equals a bundled seed song passes without testing anything.

What went wrong: in g11 the Import-with-AI E2E spec saved a Hebrew song titled "שיר הבוקר". A fresh profile seeds the bundled fixture he_plain.cho with that same title, so "library lists both titles" was true before the import, and "open the song" opened the seed. A mutant reply with the chord removed still passed. The chord check also matched any `bdi[dir=ltr]` in the song pane, which includes the sounding-key header.

How it was detected: the task evaluator ran mutants in a scratch copy (chord removed → still green) and dumped the pane text.

How to avoid: give every E2E test song a title that appears in no file under packages/test-fixtures/fixtures or samples (grep first) and assert exactly one library item matches it. Select chords with chord-render's markup (`bdi.chord[data-chord]`), not by direction alone, and keep the test key different from the asserted chord. Always prove an E2E assertion with a mutant that should make it fail. e2e/specs/setlists.e2e.ts still uses the colliding title (follow-up).
