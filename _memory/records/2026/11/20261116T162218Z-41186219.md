Decision (G5 search): the bundled songs become DB rows. Rust embeds every samples/*.cho and non-canonical packages/test-fixtures/fixtures/*.cho via include_str! (db::seed::bundled_songs). It seeds them once, in one transaction, gated by app_meta key `bundled_seeded` (value = count), and only from DbState::open.

Alternatives considered:
1. Keep the bundled library in memory with a TS port of normalize_he and search both (no user-DB writes, but two normalizers to keep identical).
2. Seed from the frontend via saveSong when listSongs is empty (re-seeds whenever the DB empties; logic lives in the UI).

Rationale: one Rust normalizer for index, query and snippet; search exercises the real IPC path; deletions persist because the flag is never re-evaluated.

Consequences for later goals:
- Adding a song under samples/ or fixtures/ now also needs a seed.rs entry; tests enforce embedded set == disk set.
- Bundled-song updates never reach an existing user DB.
- Test fixtures are permanent in user libraries (one sorts first), so a future goal may seed samples/ only or pick a default song.
- A seeding failure leaves an empty-but-usable DB and retries next launch.
- In-memory test states never seed; only file-backed DbState::open does.
