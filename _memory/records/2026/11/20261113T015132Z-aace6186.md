Pitfall: cross-platform launch-smoke scripts look right and pass their criteria but hide edge-case defects; four were found only by an adversarial evaluator in G0 (task 04, three fix cycles).

What went wrong: (1) bash `tr … | grep -qx SHIR_READY` under `set -o pipefail` reports a false "no marker" on logs >~200 KB (grep -q exits early, tr gets SIGPIPE 141). Fix: `grep -x … >/dev/null`. (2) A Windows orphan check using `Get-CimInstance Win32_Process | ? CommandLine -like '*tag*'` matches the querying powershell.exe itself, so it always reports a leftover process. Fix: also filter `$_.Name -eq 'PING.EXE'`. (3) `timeout -k` returns 137 (not 124) when the child ignores SIGTERM. (4) PowerShell parity: a non-launchable binary must hit the same usage exit 2 as bash; `catch [System.MissingMethodException]` is wrong for missing .NET methods (PowerShell throws RuntimeException) — probe with GetMethod instead; avoid `Kill($true)` (absent in PS 5.1); keep .ps1 ASCII (PS 5.1 reads BOM-less UTF-8 as cp1252, an em dash breaks parsing).

How detected: evaluator repro stubs (900 KB log, `trap '' TERM`, chmod -x, group-exec-only, bad-format binary) run through both runners, plus mutation proofs. Avoid: every fix needs a test that fails when the fix is reverted; give vitest spawnSync tests an explicit timeout (default 5 s); prove Windows-only paths on the windows-latest leg.
