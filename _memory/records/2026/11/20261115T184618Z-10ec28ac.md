Pitfall: a once-guard meant to collapse React StrictMode's double effect was tested only with sequential awaited calls, so moving the flag to after `await emit(...)` still passed every test.

Where: apps/desktop/src/uiReady.ts (`signalUiReady`), goal desktop-viewer-polish task 03.

Detection: the task evaluator ran a mutation in a scratch worktree with `signalled = true` placed after the try/catch. All 6 tests passed. A probe with `await Promise.all([signalUiReady(), signalUiReady()])` failed on the mutant and passed on the real code.

Avoid: when a requirement says to set state before an await so that same-tick callers are deduplicated, add a concurrent test (`Promise.all` of two calls, expecting one side effect) next to the sequential one. Then prove it with the flag-after-await mutation.
