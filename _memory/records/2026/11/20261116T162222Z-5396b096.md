Goal g5-search (Shir MVP G5: niqqud-insensitive search). Outcome: shipped on branch feat/g5-search as 7 task commits (5965a6b…ae89f4b) on base 0b3855b. Phase 5 audit APPROVED, Quality Checks green, QA gate PASS. A PR follows after docs.

Built:
- SearchHit { song, snippet } contract through tauri-specta bindings and storage.ts.
- normalize_he gains an in-word mark-deletion step. The marks are ׳ ״ " ' ’ ʼ; one is deleted only when both neighbours are letters that are not marks, so צה״ל = צה"ל = צהל and Ka’tamar = katamar. A side effect: `tamar` no longer matches `Ka’tamar`.
- Migration V2 creates app_meta and rebuilds songs_fts inside the migration transaction via M::up_with_hook. A failed rebuild leaves user_version at 1.
- db::seed embeds the 17 bundled .cho files (include_str!). It seeds them once in one transaction, gated by the app_meta key bundled_seeded, and only from DbState::open. A failure is logged and non-fatal.
- search_songs returns a lyric snippet: the first matching original line, niqqud kept, a 160-char cut that never orphans a combining mark, null for title/artist-only matches. One shared tokenizer serves the FTS MATCH expression and the snippet.
- Desktop sidebar: a DB-backed title-sorted list, a 150 ms debounced search with stale-response tokens, and a read-only bundled fallback with a notice.
- Two original CC0 twin samples (Hebrew + transliteration). Copyrighted user charts were kept only in the git-ignored .local/qa-songs/.

Key decisions:
- Seed via embedded corpus + flag rather than a TS-side search.
- English-only UI strings, following the existing convention.
- trace: blind because V2 rewrites user data.
- The user's standing rule "decide follow-ups with the recommended option and notify" was applied throughout, including the Phase 3 cap escalation (patch + one targeted re-evaluation).
