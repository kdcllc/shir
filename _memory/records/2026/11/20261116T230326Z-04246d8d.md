Pitfall (G6 orchestration): goals with `trace: blind` require a fresh consumer-trace-mode evaluator spawn after pre-flight and BEFORE Phase 3 attempt 1, with its diff merged into goal.md `## Consumers` and trace-lint re-run and logged. In G6 the orchestrator skipped it; the Phase 3 evaluator could not verify it from orchestration-log.md and counted it as a required revision on the last allowed attempt, forcing an escalation. When the trace finally ran it found 11 consumers the planner missed, including real breakers: scripts/g2-contract.test.ts scans a fixed chord-core file list (a new import.ts would silently skip API-doc coverage), commands/mod.rs asserts the exact command count, and g5b-contract negative tests depend on log_webview_error staying last in collect_commands!.

Second, related pitfall: after every goal/task amendment, criteria-evidence.md goes stale (new ACs, renamed -t filters, new corrective tasks). Evaluators treat a missing evidence entry as a hard-rule failure. Refresh it in the same step as the amendment.

How to avoid: put the blind-trace spawn on the pre-flight checklist whenever goal.md phases has trace: blind; after any amendment, grep criteria-evidence.md for each changed AC id and test name before re-evaluating.
