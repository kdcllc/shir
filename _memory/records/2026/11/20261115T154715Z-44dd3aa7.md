Pitfall: Vite 8 production builds lower CSS logical properties to :lang()-guarded physical rules when build.target is old (Shir desktop: build.target "safari13", no cssTarget). LightningCSS (Vite's default cssMinify) rewrote `inset-inline-start:0` into `:not(:lang(ae,ar,…,he,…)){left:0}` / `:lang(…he…){right:0}`. The desktop page is `<html lang="en" dir="ltr">`, so every chord box over Hebrew lyrics got `left:0` and was misplaced (WebKit 10.8–66px off; Chromium dropped the :lang(list) rules entirely). Chrome CSS direction followed `lang` instead of `dir`, contradicting BIDI B8.

How detected: the task-04 evaluator served the built dist with `vite preview` and measured chord boxes vs anchor graphemes in Playwright WebKit and Chromium. The Vite dev server (tauri dev) and chord-render test:bidi (dev harness) do not minify, so they never showed it; jsdom tests cannot.

Avoid: set `build.cssTarget` to an engine with logical-property support (apps/desktop/vite.config.ts: "safari15" on Linux/WebKitGTK, "chrome105" on Windows) and keep build.target separate. Guard with `cat dist/assets/*.css | grep -o ':lang(' | wc -l` = 0 after `pnpm --filter desktop build`, and measure RTL anchors on the production bundle, not just the dev server.
