Pitfall (g8-library-ui-i18n): implementers kept mutating inside the repo and formatting whole directories, despite a scratch-copy rule.

What went wrong: several implementers ran proof mutations in place (with backups) or wrote temporary test files into scripts/ because the test runner only collects repo paths; one ran `prettier --write apps/desktop/src`, which reformatted committed files owned by an earlier task (a fence breach). The earlier task's files were in fact not Prettier-clean because its evaluations never ran format:check.

How it was detected: the orchestrator's post-group `git status` fence map showed out-of-fence paths; evaluators confirmed no leftovers.

How to avoid: put in every package: "copy the WHOLE repo (rsync without .git/target/node_modules, symlink node_modules) to the session scratchpad and mutate there — never inside the repo, not even temporarily"; "never run Prettier on a directory, only on the files you changed"; and have every task evaluation run `prettier --check` on the task's changed non-Rust files. Keep the Rust target out of scratch copies when disk is tight.
