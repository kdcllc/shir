Pitfall: acceptance criteria whose true-negative/true-positive evidence was recorded on hand-made samples passed pre-flight but were wrong against real tools (G0 Phase 3 needed 3 attempts and a user escalation).

Examples: a peer-warning grep on `pnpm install --frozen-lockfile` output (frozen installs never print peer issues — use `--resolution-only`); an exact markdown-header grep that fails on prettier-padded tables (prettier always pads columns; use a whitespace-tolerant regex); a `yaml.safe_dump` substring check that wraps long lines at width 80; a pwsh `[ref]$e` ParseFile one-liner referencing an undefined variable; a node one-liner whose `\s` escapes were lost through markdown → shell quoting.

How detected: evaluators re-ran each criterion on real tool output (real pnpm 10.34.9 runs, real prettier 3.10.1 formatting, real pwsh).

Avoid: record TN/TP by running the actual tool (scratch workspace, real formatter) on both the correct shape and an injected violation; prefer python+yaml / small scripts over escape-heavy one-liners embedded in markdown; re-run every criterion extracted verbatim from the task file (`sed` the command out) rather than a hand-retyped copy.
