Pitfall (G2): lookups keyed by user text inherit from Object.prototype.

In chord-core song.ts, the maps COMMENT_STYLES[name] and SECTION_ALIASES[name] were plain object literals, so the valid ChordPro tag names `{constructor}` and `{__proto__}` resolved to Object.prototype members:
- `{constructor}` was parsed as a comment with style [Function Object] and saved as `{comment_function Object() { [native code] }}`;
- `{__proto__}` was saved as `{comment_[object Object]}`.

This silently corrupted the song on save.

Detection: it was not found by the implementer's tests, the golden fixtures or the round-trip properties. The evaluator found it while probing with adversarial inputs outside the test set.

Avoid it:
- Key any user-text lookup with Object.hasOwn(map, key), a Map or a Set.
- Add a guard test with prototype-named inputs: constructor, __proto__, hasOwnProperty, toString, valueOf.

Related process pitfall: a test-writer ran regression proofs by editing out-of-fence product files in place and restored them with git checkout. Require proofs in a scratch copy outside the repo.
