Decision: dependency versions in Shir are chosen as "the latest published version within a pinned major that satisfies every peer range in the pnpm catalog" — not the registry `latest` tag — and an unmet-peer warning is a failure (checked with `pnpm install --resolution-only --reporter=append-only` plus a lockfile cmp, because `pnpm install --frozen-lockfile` never prints peer issues).

Alternatives considered: always-latest (rejected: in Nov 2026 typescript 7.0.2 ships no compiler API and breaks typescript-eslint's peer `<6.1.0`; stylelint 18 breaks stylelint-use-logical `<18`); caret ranges with the lockfile as truth (rejected: spec requires exact pins recorded in docs/STACK.md).

Pinned majors at G0: typescript 6.0.x, eslint 10.x with @eslint/js same MAJOR (not same version — @eslint/js 10.0.1 vs eslint 10.14.0), stylelint 17.x + stylelint-config-standard 40.x, @tauri-apps/cli and api 2.12.x, Rust crate tauri 2.12.5 (major.minor = npm), tauri-build follows tauri's own build-dependency (2.7.4, versioned independently).

Consequences: scripts/stack-consistency.test.ts enforces STACK.md = catalog = pnpm-lock = Cargo.lock and the tauri↔@tauri-apps major.minor rule; every upgrade must update STACK.md in the same change. TypeScript 6 defaults `types` to [] so each tsconfig lists needed ambient types (node, vite/client).
