Pitfall 1 — B4 overlap pass computed collisions in LOGICAL coordinates (converting x by line direction). In an RTL line containing an LTR run (e.g. Hebrew line with "rock and roll"), logically consecutive chords are visually left-to-right, so the logical conversion reported collisions that did not exist and added ~640px of padding, wrapping the line. jsdom unit tests with mocked rects did not catch it; the Playwright bidi suite (checklist 4 on mixed_he_en, both engines) did. Fix: detect collisions only from physical getBoundingClientRect intervals grouped by visual row; use DOM order only to pick which element gets padding-inline-end, and pad by overlap + gap on the side the later chord lies. Cap 8 iterations.

Pitfall 2 — ChordSheetJS 18: `{direction: rtl}` is NOT parsed as metadata (it is an unknown Tag); only `{meta: direction rtl}` lands in song metadata, and conflicting repeated metadata becomes an array. Read both forms explicitly and verify parser facts against the library before writing goldens.

Avoid: test bidi layout in real engines early; never trust a library-behaviour assumption without a probe.
