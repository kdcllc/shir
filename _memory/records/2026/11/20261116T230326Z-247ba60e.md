Decision (G6, user-confirmed Q&A rows 12a and 13): when importing plain-text chords-over-lyrics, chord columns over an RTL lyric line are mapped with a bidi-run-aware "mirror" model by default, with "logical" (column = grapheme index) as the Flip alternative.

Model: the sheet is assumed typed in an LTR-paragraph plain-text editor. A simplified UAX#9 pass over the lyric's graphemes (types R = Hebrew/Arabic script grapheme, L = other letters, EN = digits; W7; N1/N2 with line edges = L; levels L0/R1/EN2; L2 reversal) yields vis[c] = logical index shown at visual column c. A chord span [s,e): rule 1 if vis[s] has even level use it; rule 2 else use vis[e-1]; rule 3 past the lyric end clamps (chord-past-end warning). Forward snap off whitespace applies after. For pure-Hebrew lines this reduces exactly to i = n − e.

Alternatives rejected: W = max(chordLine, n) (mixed two layout models; shifted chords when the chord line is longer than the lyric), right-aligned W = chord-line length (RTL web page model), plain whole-line reversal (mirrors embedded Latin words — `[Dm]blues` instead of `bl[Dm]ues`), per-file three-mode choice (more UI and fixtures).

Consequences / known gaps: W4/W5 number separators and Arabic-Indic digits (classed R) are not modelled; a chord straddling an RTL→LTR boundary anchors on its LTR end. Code: packages/chord-core/src/import.ts.
